**Objetivo**: Adicionar `--limit-memory` + `--limit-cpu` aos top 6 consumers e prune avançado para liberar disco.

## TL;DR

- **6 serviços** receberam `limit-memory=2G` + `limit-cpu=1.0`
- **Disco liberado**: 128G → 118G = **10GB recuperados** (uso 66% → 61%)

## Memória do Host — antes/depois

```
=== ANTES ===
Mem: 15Gi total, 8.8Gi used, 1.4Gi free, 5.9Gi buff/cache, 6.8Gi available

=== DEPOIS (aplicando limits) ===
Mem: 15Gi total, 8.8Gi used, 1.4Gi free, 5.9Gi buff/cache, 6.8Gi available
```

Memória atual do host **não mudou** porque os limits Swarm funcionam como **capping kernel-level** (cgroup v2) — eles **evitam** OOM kill mas não comprimem imediatamente. O ganho vem da proteção contra runaway spikes:

- **Antes**: sonarqube + sourcegraph sozinhos usam 2.55GB hoje e poderiam consumir todo o host em caso de bug/vazamento.
- **Depois**: cada um desses 6 services tem teto de 2GB. Pico teórico combinado = 12GB, deixando 3GB de folga para os outros 83 serviços + kernel.
