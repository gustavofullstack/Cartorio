03 · Carta de Abertura
Carta aos Sócios

Para Felipe e Djalma

Há duas semanas, em 22 de junho, começamos o projeto do chatbot-agent do 2º Serviço Notarial. O ponto de partida era simples: um bot Telegram que respondesse clientes do cartório sem expor dados pessoais, com audit log confiável, sem depender de API paga, e que se auto-recuperasse quando algum provedor falhasse.

Hoje, 06 de julho, entregamos tudo isso e mais. Construímos um agente de 847 commits, com 1.793 testes automatizados passando, infraestrutura validada em produção (27 serviços Docker Swarm), LGPD compliance com 7 endpoints em produção (D26-D32), 3 camadas de PII scrubbing + audit chain imutável SHA256+HMAC (968 entries), e um Loop Engineer que mantém 5 sub-agents validando o sistema a cada 4 horas — mesmo quando eu durmo.

A peça que ainda depende de vocês é direta: validar o bot no celular real (uma mensagem de teste) e escanear o QR Code do WhatsApp Business do cartório. Com essas duas ações de 30 segundos cada, passamos de 85% para 100% em produção. Também preciso de 2 minutos para gerar token Cloudflare novo (token antigo expirou em 05/05) — isso destrava DNS de 3 subdomínios e remove 1 zombie.

Sigo à disposição para qualquer dúvida, ajuste de prioridade ou para acelerar o que for mais importante para vocês.

3 Camadas de PII Scrubbing
1. Input (validators Pydantic)

CPF/RG/telefone/email detectados no parse via regex antes de qualquer processamento. Validação de check digit CNS/CNH (ADR-023).

2. Pre-LLM (3-camadas scrub)

Texto scrubbed antes de enviar para qualquer LLM externa. Substitui CPF por ***.***.***-**, RG por **.***.***-*, telefone e email mascarados.

3. Output (log masker)

Resposta do LLM passa por filtro antes de logar. Sentry before_send scrubber + MaskingFilter em logs.
