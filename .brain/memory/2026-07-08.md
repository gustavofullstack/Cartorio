## Lesson 154 — Cloudflare trycloudflare tunnel ephemeral morre em VPS restart. Usar dominio Traefik direto como webhook URL (2026-07-08)

### Sintoma
Webhook bot Telegram respondia 530 wrong response + pending_update_count=2 + ip_address=104.16.231.132 (Cloudflare). Gustavo reportou "botoes nao funcionam" pela enesima vez.

### Root cause
O webhook url estava em `https://end-controversy-book-seems.trycloudflare.com/api/v1/telegram/webhook`.
Esse tipo de url `trycloudflare.com` vem de `cloudflared tunnel --url http://localhost:8000` (modo ephemeral, sem credenciais).
Quando a VPS reinicia (15 dias uptime mas o processo cloudflared morreu em algum restart anterior), o tunnel morre e o DNS `trycloudflare.com` deixa de resolver.

Mas a API backend ja esta exposta via Traefik direto em `https://api.2notasudi.com.br/api/v1/telegram/webhook` (validado: POST retorna `{"status":"ok","chat_id":-1004331849032,"response_sent":true}` em <1s).
Solucao: repointar webhook para o dominio Traefik direto, eliminando dependencia do tunnel.

### Fix aplicado (12:36 BRT)
```bash
curl -X POST "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook" \
  -d "url=https://api.2notasudi.com.br/api/v1/telegram/webhook" \
  -d "allowed_updates=[\"message\",\"callback_query\",\"my_chat_member\"]" \
  -d "drop_pending_updates=true"

# validacao:
# {"url":"https://api.2notasudi.com.br/api/v1/telegram/webhook",
#  "ip_address":"187.77.236.77",        <- VPS real
#  "pending_update_count":0,
#  "last_error_message":null}            <- sem 530
```

### Por que a abordagem do tunnel anterior falhou
- cloudflared binary NAO esta instalado no VPS (sem `which cloudflared`, sem systemd unit)
- Config `~/.cloudflared/config.yml` NAO existe
- Tunnel ephemeral so funciona enquanto processo estiver vivo; nao tem mecanismo de restart automatico sem credenciais
- N8N/Evolution/Chatwoot ja acessam API via Traefik direto (porta 443) com sucesso. Telegram tambem pode.

### Quando usar tunnel
- Se a API nao tiver dominio publico proprio (caso de desenvolvimento local)
- Nunca em prod. Sempre apontar webhook para dominio Traefik publico + validar com `getWebhookInfo`

## Lesson 155 — Modulo-level mutable state > callable-attribute para mypy strict (FIX 2026-07-08 16:50)

### Contexto
mypygate falhava em `telegram.py:176/178/185` (3 erros `attr-defined`):
```python
def _get_tg_pool() -> httpx.AsyncClient:
    ...
    if not hasattr(_get_tg_pool, "_loop_id"):
        _get_tg_pool._loop_id = 0     # mypy: Callable[[], AsyncClient] no tem attr _loop_id
```
Esse erro existia HA SEMANAS. Foi introduzido no commit f3a9958 (turno 49).
Ninguem corrigiu porque o gate mypy eh pre-push (manual), nao pre-commit.

### Causa raiz
Padrao antigo: usar a propria funcao como namespace (setando attr nela via `setattr(callable, ...)`).
Funciona em runtime (Python permite), mas mypy strict em Callable[...] nao aceita attr-defined.

### Fix canonico
Mover estado mutavel para variavel de modulo:
```python
_TG_HTTP_POOL: httpx.AsyncClient | None = None
_TG_HTTP_POOL_LOOP_ID: int = 0

def _get_tg_pool() -> httpx.AsyncClient:
    global _TG_HTTP_POOL, _TG_HTTP_POOL_LOOP_ID
    ...
    if _TG_HTTP_POOL_LOOP_ID != current_loop_id:
        _TG_HTTP_POOL = httpx.AsyncClient(...)
        _TG_HTTP_POOL_LOOP_ID = current_loop_id
    return _TG_HTTP_POOL
```
